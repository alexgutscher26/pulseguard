## The Math of Check Frequency: 1,440 Checks vs 288 Checks

The fundamental difference between PulseGuard and UptimeRobot's free tiers comes down to sampling resolution:

- **UptimeRobot Free Tier:** 5-minute interval (300 seconds) = **288 checks per day** per target.
- **PulseGuard Free Tier:** 1-minute interval (60 seconds) = **1,440 checks per day** per target.

That is a **500% increase in data resolution**.

```
UptimeRobot (5m checks):
[Check 1: OK] ------------------ 5 mins ------------------ [Check 2: DOWN]
                      ^--- 4 min outage happens here ---^
                      (Customers complain, zero alerts fired)

PulseGuard (1m checks):
[Check 1: OK] - 1m - [Check 2: OK] - 1m - [Check 3: DOWN] - 1m - [Check 4: RECOVERED]
```

If an API endpoint drops for 3 minutes due to a memory leak or database lockup, UptimeRobot's 5-minute timer has a 60% chance of missing the outage entirely. When it does capture the failure, your Mean Time to Detect (MTTD) averages 2.5 minutes and can take up to 5 minutes.

With PulseGuard's 60-second checks, worst-case detection latency is 60 seconds, and average detection time drops to 30 seconds.

## Single-Region Polling vs Edge Quorum Consensus

Detecting an outage quickly is only half the battle. The other half is avoiding false positives — getting woken up at 3:00 AM because a single AWS region experienced transient packet loss.

### UptimeRobot's Polling Architecture

UptimeRobot polls targets sequentially from a primary regional worker node. If the primary node gets a connection timeout, it retries from a secondary node. While functional, this centralized polling model suffers from network transit latency and regional routing anomalies between AWS Datacenters.

### PulseGuard's Edge Quorum Architecture

PulseGuard operates natively on Cloudflare's global edge runtime across 50+ locations. When an edge worker detects a non-2xx status code or TCP timeout:

1. It immediately triggers a **quorum request** to two independent edge nodes in different geographical regions (e.g., Frankfurt and Singapore).
2. All nodes execute simultaneous parallel pings against your target endpoint.
3. An alert is dispatched **only if a 2/3 multi-region consensus** confirms the failure.

```ts
// PulseGuard Edge Quorum Consensus Logic (Simplified)
async function verifyTargetHealth(targetUrl: string): Promise<HealthStatus> {
  const localResult = await pingTarget(targetUrl);
  if (localResult.ok) return { status: "UP", latencyMs: localResult.latency };

  // Local probe failed — dispatch parallel verification to secondary edge regions
  const [regionA, regionB] = await Promise.all([
    dispatchEdgeProbe("iad-us-east", targetUrl),
    dispatchEdgeProbe("fra-eu-central", targetUrl),
  ]);

  const failures = [localResult, regionA, regionB].filter((r) => !r.ok).length;

  // Require 2/3 consensus before declaring an incident
  if (failures >= 2) {
    return { status: "DOWN", verifiedBy: failures, timestamp: Date.now() };
  }

  return { status: "DEGRADED", note: "Transient regional routing noise ignored" };
}
```

This multi-region voting pipeline executes in under 800ms, completely eliminating false alarms caused by regional CDN drops or ISP routing hiccups.
