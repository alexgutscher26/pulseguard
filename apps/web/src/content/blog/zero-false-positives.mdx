False positives are the silent killer of on-call trust. When alerts fire for phantom network blips, engineers start muting notifications. Eventually, a real production outage slips through unnoticed because everyone assumed it was another false alarm.

We built PulseGuard's edge verification mesh to solve this permanently: **zero false positives**, no matter how many endpoints you monitor.

---

## Why Single-Probe Verification Fails

The standard approach used by legacy monitoring tools is a single-node check:

```
[Single Cloud Node in Virginia] ---- (ISP Routing Flap / Packet Loss) ----x----> [Your Server]
                                    |
                                    v
                           [Sends 3 AM False Alarm]
```

One poller server in one region issues an HTTP request. If that probe experiences local packet loss, DNS timeout, or socket contention, it assumes your server is down and triggers a page. Adding a sequential "retry in 30 seconds" helps only slightly if the same node hits the same local transit issue.

---

## PulseGuard's 2/3 Multi-Region Quorum Pipeline

PulseGuard takes a distributed consensus approach. When an edge probe detects an issue:

| Step                      | Action                                                                     | Execution Window |
| :------------------------ | :------------------------------------------------------------------------- | :--------------- |
| **1. Origin Detection**   | Local edge worker detects non-2xx status or timeout                        | Immediate (0ms)  |
| **2. Parallel Dispatch**  | Dispatches verification pings to 2 secondary global regions                | < 200ms          |
| **3. Quorum Vote**        | Durable Object Actor aggregates votes across all 3 probes                  | < 400ms          |
| **4. Dispatch / Resolve** | Alert triggers only if at least 2 of 3 independent regions confirm failure | < 600ms total    |

If a transient ISP drop only affects Virginia, the secondary probes in Frankfurt and Singapore report `200 OK`. The transient blip is recorded as degraded regional noise, and your on-call engineer sleeps undisturbed.
